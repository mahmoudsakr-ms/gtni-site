## Architecture

Single Next.js app that serves both the public frontend and the Payload CMS admin panel from the same codebase (`withPayload()` wraps `next.config.mjs`).

```
src/
├── app/
│   ├── (frontend)/     # Public site: about-gtni, admission, courses,
│   │                   #   news-events, nursing-programs, scholarships,
│   │                   #   student-services, vacancies, layout, globals.css
│   ├── (payload)/      # Payload admin panel route group
│   └── api/            # Custom API routes: revalidate, custom-news-events
├── collections/        # Payload collections: Users, Media, MediaCategory,
│                        #   NewsCategory, NewsEvents
├── globals/             # Payload globals (singleton content types):
│                        #   Header, Footer, Home, Settings, AboutGTNI,
│                        #   Admission, Courses, NursingPrograms,
│                        #   Scholarships, StudentServices, Vacancies,
│                        #   NewsEvents
├── components/          # React components (About, RichText, Scholarships,
│                        #   animations, payload, ui — shadcn primitives)
├── elements/             # Custom Payload admin UI overrides: Avatar,
│                        #   BeforeLogin, Dashboard, Logo, Nav
├── themes/theme1/        # Site theming
├── utilities/             # Includes custom revalidation helpers
│                        #   (withCollectionRevalidate / withGlobalRevalidate)
├── lib/
├── styles/
├── migrations/            # Payload/SQLite migrations (timestamped .ts/.json pairs)
├── payload.config.ts     # Central Payload CMS configuration
└── payload-types.ts       # Auto-generated TS types (via `pnpm generate:types`)
```

### Notable design points
- Collections and globals are wrapped with custom `withCollectionRevalidate` / `withGlobalRevalidate` helpers — likely triggers ISR revalidation on content changes (see `src/app/api/revalidate/route.ts`).
- Email adapter switches automatically: uses **Resend** if `RESEND_API_KEY` is set, otherwise falls back to SMTP via Nodemailer (default host `smtp.office365.com`).
- Admin panel has custom branding/components (custom Dashboard, Logo, Nav, Avatar, BeforeLogin screen), dark theme, admin title suffix "GTNI Admin".
- `next.config.mjs` defines a large set of permanent (301) SEO redirects from a legacy site's URL structure (e.g. `/about` → `/about-gtni`, `/ar/*` Arabic paths collapsed into the main routes).
- Server actions body size limit raised to 100MB (for uploads); nginx `client_max_body_size 100M` matches this.
- Webpack config extended to resolve `.cjs/.cts`, `.mjs/.mts` extension aliases.
- `serverExternalPackages`: `libsql`, `@libsql/client` (kept out of the Next.js bundle).

## Environment Variables (`.env` — keys only, values not disclosed)

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | SQLite file path (e.g. `file:./.db`) |
| `PAYLOAD_SECRET` | Payload CMS encryption/auth secret |
| `CACHE_REVALIDATION_TOKEN` | Secret token for the custom `/api/revalidate` endpoint |
| `NEXT_PUBLIC_SERVER_URL` | Public site URL (`https://gtni.edu.eg`) |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` | Fallback SMTP email config |
| `EMAIL_FROM_NAME` / `EMAIL_FROM_ADDRESS` | Outgoing email sender identity |
| *(optional, referenced in code)* `RESEND_API_KEY` | Enables Resend email adapter when present |

## Data & Media Persistence

- **Database**: single SQLite file at `/var/www/gtni/.db` (must be preserved across deploys/backups — do not delete or overwrite).
  - A backup snapshot pattern exists: `.db.backup_YYYYMMDD_HHMMSS`.
- **Uploaded media**: `public/media` (per `README_DEPLOY.md` — verify path in `Media` collection config before relying on this).

## Deployment / Process Management

- **Process manager**: PM2, app name `gtni`
  - Config: `ecosystem.config.cjs`
  - Script: `node_modules/next/dist/bin/next start -p 3000`
  - Mode: fork, 1 instance, `NODE_ENV=production`, max memory restart 2G
  - Logs: `/var/log/pm2/gtni-{error,out,combined}.log`
- **Reverse proxy**: nginx (v1.24.0)
  - Config: `/etc/nginx/sites-available/gtni` (symlinked in `sites-enabled`)
  - Proxies `gtni.edu.eg` / `www.gtni.edu.eg` (ports 80→443 redirect) to `http://127.0.0.1:3000`
  - `client_max_body_size 100M`
  - SSL via Let's Encrypt / Certbot (`/etc/letsencrypt/live/gtni.edu.eg/`)
- **OS**: Ubuntu 24.04.4 LTS

## Standard Build/Run Commands (from `package.json`)

```bash
pnpm install --shamefully-hoist --node-linker=hoisted   # per README_DEPLOY.md, required for Payload
pnpm run generate:importmap
pnpm run generate:types
pnpm run build     # NODE_OPTIONS --max-old-space-size=8000
pnpm run start      # or: pm2 start ecosystem.config.cjs
```

Dev: `pnpm run dev` (or `pnpm run devsafe` to clear `.next` first)
Lint: `pnpm run lint`
Tests: `pnpm run test` (`test:int` = Vitest, `test:e2e` = Playwright)
Payload CLI: `pnpm run payload`

## Notes for Further Development

- This is a **Payload CMS 3 + Next.js 15** monorepo-style single app — content types are defined as code (`collections/`, `globals/`) and changes to their schema require a generated migration (`src/migrations/`) plus `pnpm run generate:types`.
- No git repository is currently initialized in `/var/www/gtni` — there's no version-controlled history on this VPS; consider setting one up (or confirm if version control is maintained elsewhere, e.g. locally/GitHub, before assuming this is the source of truth).
- Full deployment walkthrough (bilingual AR/EN) already exists at `README_DEPLOY.md` in the project root — consult it for step-by-step production setup.
